# Agents

Generated from `agents/*.md` frontmatter. Agents are addressed as `odoo-master:<name>` (Agent tool `subagent_type`).
Plugin agents cannot set hooks, MCP servers or permission modes; those come from the plugin's `hooks/hooks.json`, `.mcp.json` and your settings.
Agents without a `tools` list inherit all tools, including MCP tools. Ticket, GitHub, integration and orchestrator agents need that to reach MCP servers.

Every agent ends with the reporting contract `STATUS: DONE | DONE_WITH_CONCERNS | NEEDS_CONTEXT | BLOCKED` and cites `path:line` for claims.

## Model choices
- `opus` for the architect, security, migration, database and code reviewers, where reasoning depth matters more than cost.
- `sonnet` for analysis, documentation and ticket/GitHub agents, which do structured, lower-risk work.
- `inherit` for implementers, so they follow the session's model.
Change these by copying an agent into `.claude/agents/` in your project; project agents take precedence over plugin agents.

## Selection
Agents are chosen per workflow step (`workflows/*.yaml` → `agent`). The orchestrator never runs agents a step does not need. To disable an optional agent, list it in `.odoo-master/config.yaml` → `agents.disabled` and use a project workflow without it.
